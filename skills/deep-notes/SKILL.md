# Deep Notes · 契约卡

把知识内容做成一篇外行能读懂、双击即可离线打开的深色单文件 HTML 笔记。怎么讲清楚一件事你已经会了，本文件只规定**默认值、资产契约、不能漂移的边界**，不复述方法论。

输入可以是文件、URL、粘贴文本或一个主题。材料过少且主题过于专业时，先问用户，不硬编。

## 硬边界（违反即为不合格）

1. **零点击读懂**：核心知识全部默认展开。点击只允许用于：目录跳转、自测答案、确有必要的前后状态对比。禁止 Tab 切换、弹窗、手风琴折叠正文、纯装饰动画；不为展示技术加交互。
2. **不编造**：无材料时凭可靠知识写；没把握的精确数字、人名、年份、出处一律不写精确值。
3. **讲透不讲全**：3-5 个模块讲深，不抄目录、不凑篇幅。
4. **单文件离线**：成品只有一个 `.html`，CSS/JS 全内联（由脚本注入），双击可开；首行保留 `<!-- Generated by Trae Work -->`。
5. **Hero 必须照抄模板结构**：`hero` / `hero__inner` / `hero__eyebrow` / `hero__summary` / `hero__meta` 类名和嵌套必须和 `template.html` 一致，禁止自创 `.hero-tag`、`.hero-stats` 等替代结构；禁止手写 CSS/JS 覆盖公共样式。
6. 带交互的组件（滑块、雷达图、矩阵等）即使读者不操作，其结论也必须直接写在正文里。

## 结构（一行版）

**Hero**（eyebrow=小领域标签 pill；h1=一句带观点的完整长句，不是名词短语；summary=1-3 句金句式展开；meta=3-4 个横向指标，数字用主题色）→ 目录 → 3-5 个 PART 模块（每个概念走「是什么 / 为什么 / 例子 / 怎么用」，每模块配 4-6 条误区）→ 6-8 道自测（给新场景考应用，不考背诵；答案写清为什么）→ 金句或 ≤3 步行动清单收尾。

## 资产契约（这些 token 是任意规定，猜不出来）

主题写在 `<body data-theme="...">`，只能取以下值，**拼错会静默变色**：

`psyche`（默认，心理/决策/社会）｜`business`（经济商业，琥珀金）｜`gold`（哲学/方法论，金）｜`learning`（学习成长，绿）｜`tech`（科技/AI，青）｜`war`（战略/历史，红）｜`health`（医学/健康，橙）｜`slate`（中性兜底）

正文容器是裸 `<main>`，不写类名。组件只用下列类名，嵌套自由组织：

- 结构：`hero`、`toc`、`part-divider`（part-divider__label）、`<section id>`
- 内容：`callout callout--insight|warn|danger|success|info`、`quote`、`think`、`story`、`cards`+`card`（cards--2/--4 调列数，card--center/--featured）、`steps`+`step`、`compare`+`compare__col--bad|--good|--a|--b`、`pitfalls`+`pitfall`
- Hero（必须照抄结构， gradient 标题 / pill eyebrow / 主题色数字由公共 CSS 自动实现，零手写样式）：

```html
<header class="hero"><div class="hero__inner">
  <span class="hero__eyebrow">领域标签 · 如：30 分钟读懂经济学</span>
  <h1>一句带观点的完整长句，说明这个主题最本质的结论</h1>
  <p class="hero__summary">1-3 句金句式展开，读者看完就抓住全文主干。</p>
  <div class="hero__meta">
    <span>阅读时长<strong>约 30 分钟</strong></span>
    <span>核心模块<strong>N 个</strong></span>
    <span>自测题<strong>N 道</strong></span>
  </div>
</div></header>
```

- 自测（唯一必须照抄结构的组件，点击展开由公共脚本自动绑定，零 JS）：

```html
<div class="quiz-item"><div class="quiz-item__q">问题？</div><div class="quiz-item__a">答案 + 为什么</div></div>
```

冷门组件 `stats / timeline / quiz-multi / slider / btn / radar / matrix` 默认不用；确有必要时读 `assets/snippets.html` 按编号 11、12、15、16、17、18、19 取对应那一段，不要通读。

## 构建（4 步，不手写 CSS/JS）

1. `Copy-Item assets\template.html x.draft.html`（文件名自取，放任意位置均可）；
2. 填 `<title>`、`data-theme`，正文写进 `<main>`；两个哨兵 `/*__DN_CSS__*/`、`/*__DN_JS__*/` 原样保留、各一次，不要粘贴任何 CSS/JS；
3. `node assets/build.js x.draft.html` → 自动产出 `x.html`（哨兵缺失或重复会报错退出）；
4. 仅在没有 Node 时，手工把两个哨兵替换为 components.css、components.js 全文。

**不要读取** `components.css`、`components.js`、`docs/`。`examples/` 默认不读，仅当用户明确指定模仿某篇、或风格拿不准时最多读一篇。

## 交付前自查（5 条）

- Hero 是否用了 `hero__eyebrow / h1 / hero__summary / hero__meta` 结构，没有自创类名或手写覆盖样式？
- 不点任何东西，能从头读懂全文吗？
- 有没有未解释的术语、编造的精确事实？
- 成品是单个 HTML、无哨兵残留、双击能开吗？
- 交互是否只出现在白名单（目录 / 自测 / 必要对比）内？
